# Data Model (PostgreSQL 18 on Neon) — v1.1

> Companion to [`DESIGN.md`](./DESIGN.md). This DDL is the design source of truth. It's
> implemented as a Drizzle schema (`packages/db/schema/*.ts`) plus **hand-written SQL
> migrations** for everything Drizzle can't express: roles, RLS policies, `SECURITY DEFINER`
> functions, partial/`INCLUDE`/`btree_gin` indexes, composite FKs, triggers.
>
> v1.1 incorporates an adversarial review in which the DDL was applied to PostgreSQL 18.6 and
> load-tested (20 users, 130k emails). Fixes: runtime role and RLS bypass, `SECURITY DEFINER`
> design, composite tenant FKs, FK indexes (account deletion went from 21s to 0.1s), search
> under RLS, a message ledger, a quota bucket, label-race protection, idempotency constraints,
> purge completeness, and in-app triage state. The final DDL was re-tested (see §8).

## 1. Principles

- **Tenant key everywhere, enforced by FKs.**
  - Every user-owned row carries `user_id`.
  - Every parent has `UNIQUE (id, user_id)`, and children reference parents with **composite
    FKs** `(parent_id, user_id)`. A child can't point at another tenant's row: plain FK checks
    bypass RLS, so this is the only thing that stops it.
- **Least-privilege roles.** The app connects as `app_rw`, which is SQL-created and
  `NOBYPASSRLS`. It never uses the owner role (§4).
- **RLS as backstop.** It's `FORCE`d on every tenant table, driven by a transaction-local
  `app.user_id`, and fails closed.
- **Keep personal mail out.** Messages classified as personal are never stored. The
  `message_ledger` keeps a content-free record so they're never fetched again.
- **Minimize content.** No email bodies are stored:
  - The search index (`tsvector`) is computed at insert time from an excerpt that is **not
    persisted**.
  - Security-sensitive mail (OTP codes, password resets, magic links) keeps only
    subject/sender/time. No snippet, no search terms, no screenshots.
- **Narrow hot rows, wide cold rows.**
  - `email` holds only list/facet fields.
  - Heavy JSON lives in `email_analysis` (1:1).
  - Screenshots live in private Blob storage.
  - `fillfactor = 85` enables HOT updates for frequent flag changes.
- **Measurements separate from scores.** `email_analysis.features` allows re-scoring without
  re-rendering.
- **Idempotency in the database.** Every pipeline write is a safe upsert or a replace-set
  (unique keys noted inline). Aggregates are incremented only when a row was actually inserted
  (`RETURNING (xmax = 0)`).
- **IDs.** `uuid DEFAULT uuidv7()` (PostgreSQL 18). Better Auth tables keep their text ids, so
  `user_id` is `text`.

Extensions: `citext`, `pg_trgm`, `btree_gin`. All three are trusted, so a non-superuser DB
owner can install them.

## 2. Entity overview

```
user (Better Auth: user, session, account, verification — login only; no RLS)
 ├─1 user_settings
 ├─* mailbox ─1 gmail_quota
 │   ├─* message_ledger      (every Gmail message id we know: pending/stored/skipped/failed; content-free)
 │   ├─* email ─1 email_analysis
 │   │        └─* deal
 │   └─* sync_run
 ├─* sender ─* email_template
 ├─* saved_view, user_feedback, review_share, llm_usage, llm_budget, data_request
 └─  audit_log (special policies), blob_gc (deferred Blob deletion)
beta_allowlist (global, admin-managed)
```

## 3. DDL

```sql
CREATE EXTENSION IF NOT EXISTS citext;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS btree_gin;

-- Better Auth tables ("user", session, account, verification[, passkey, rateLimit])
-- are generated by `npx auth@latest generate` → drizzle-kit. Not repeated here.
-- `account` is used ONLY for app login (separate Google Cloud project, basic scopes).

-- ───────────────────────── global ─────────────────────────
CREATE TABLE beta_allowlist (                 -- invite gate (protects the unverified app's 100-user lifetime cap)
  email          citext PRIMARY KEY,
  invited_by     text,
  created_at     timestamptz NOT NULL DEFAULT now(),
  used_at        timestamptz
);

-- ───────────────────────── per user ─────────────────────────
CREATE TABLE user_settings (
  user_id                   text PRIMARY KEY REFERENCES "user"(id) ON DELETE CASCADE,
  timezone                  text NOT NULL DEFAULT 'UTC',
  ai_processing_consent_at  timestamptz,                -- in-app disclosure accepted; required before connect
  load_images_for_analysis  boolean NOT NULL DEFAULT true,  -- privacy mode = false (images-off analysis only)
  link_check_opt_in         boolean NOT NULL DEFAULT false,
  screenshot_retention_days int NOT NULL DEFAULT 30 CHECK (screenshot_retention_days BETWEEN 7 AND 365),
  backfill_window_days      int NOT NULL DEFAULT 90 CHECK (backfill_window_days IN (30, 90, 180)),
  digest_frequency          text NOT NULL DEFAULT 'daily' CHECK (digest_frequency IN ('off','daily','weekly')),
  created_at                timestamptz NOT NULL DEFAULT now(),
  updated_at                timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE mailbox (
  id                      uuid PRIMARY KEY DEFAULT uuidv7(),
  user_id                 text NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  provider                text NOT NULL CHECK (provider IN ('gmail','outlook')),
  provider_account_id     text NOT NULL,                 -- verified id_token `sub`
  email_address           citext NOT NULL,               -- users.getProfile emailAddress (push lookup key)
  status                  text NOT NULL DEFAULT 'connecting'
                          CHECK (status IN ('connecting','active','needs_reauth','paused','disconnecting')),
                          -- disconnected mailboxes are HARD-deleted by the purge job (no tombstones)
  status_reason           text,                          -- e.g. invalid_grant, domain_policy, user_request
  granted_scopes          text[] NOT NULL DEFAULT '{}',
  dek_wrapped             bytea,                         -- per-mailbox DEK wrapped by Cloud KMS (HSM)
  kms_key_name            text,                          -- full KMS key resource name incl. version
  refresh_token_enc       bytea,                         -- ver ‖ nonce ‖ AES-256-GCM(ciphertext ‖ tag)
  access_token_enc        bytea,
  access_token_expires_at timestamptz,
  refresh_lease_until     timestamptz,                   -- lease for token refresh (no lock held across HTTP)
  history_id              numeric(20,0),                 -- Gmail sync cursor (uint64); compare in SQL only
  resync_pending          boolean NOT NULL DEFAULT false,
  watch_expires_at        timestamptz,
  last_push_at            timestamptz,
  last_synced_at          timestamptz,
  needs_reauth_since      timestamptz,                   -- purge after 30 days
  backfill_state          text NOT NULL DEFAULT 'pending'
                          CHECK (backfill_state IN ('pending','running','done','failed')),
  backfill_generation     int NOT NULL DEFAULT 0,        -- bumps on re-import/resync; part of event ids
  created_at              timestamptz NOT NULL DEFAULT now(),
  updated_at              timestamptz NOT NULL DEFAULT now(),
  UNIQUE (id, user_id),
  UNIQUE (provider, provider_account_id),                -- one live binding per Google account
  UNIQUE (provider, email_address)                       -- push lookup is by address
);
CREATE INDEX mailbox_user      ON mailbox (user_id);
CREATE INDEX mailbox_watch_due ON mailbox (watch_expires_at) WHERE status = 'active';

-- Shared per-mailbox Gmail quota bucket; EVERY Gmail call site reserves units here (DESIGN.md §5.2).
CREATE TABLE gmail_quota (
  mailbox_id              uuid PRIMARY KEY,
  user_id                 text NOT NULL,
  tokens                  real NOT NULL DEFAULT 5500,    -- capacity 5,500 units, refill 5,500/min (limit is 6,000)
  updated_at              timestamptz NOT NULL DEFAULT now(),
  FOREIGN KEY (mailbox_id, user_id) REFERENCES mailbox (id, user_id) ON DELETE CASCADE
);

CREATE TABLE sender (
  id                      uuid PRIMARY KEY DEFAULT uuidv7(),
  user_id                 text NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  address                 citext NOT NULL,
  display_name            text,
  domain                  text NOT NULL,                 -- registrable domain (tldts)
  esp_platform            text,
  esp_mta                 text,
  first_seen_at           timestamptz NOT NULL,
  last_seen_at            timestamptz NOT NULL,
  seen_before_window      boolean,                       -- sender existed before the backfill window ("New senders" correctness)
  email_count             int NOT NULL DEFAULT 0,
  unread_count            int NOT NULL DEFAULT 0,
  emails_per_week         real,
  frequency_band          text CHECK (frequency_band IN ('daily','several_weekly','weekly','monthly','rare')),
  read_rate_60d           real,                          -- read in Gmail OR opened in app
  type_distribution       jsonb NOT NULL DEFAULT '{}',
  primary_type            text,                          -- computed prior
  type_override           text,                          -- user correction ("always classify as …")
  one_click_unsubscribe   boolean,
  list_unsubscribe        jsonb,                         -- latest parsed header (user-initiated action only)
  unsubscribed_at         timestamptz,                   -- user clicked "open unsubscribe page" → "still sending" detection
  auth_summary            jsonb,
  avg_design_score        real,
  brand_profile           jsonb,
  user_importance_bias    smallint NOT NULL DEFAULT 0 CHECK (user_importance_bias BETWEEN -2 AND 2),
  muted                   boolean NOT NULL DEFAULT false,
  created_at              timestamptz NOT NULL DEFAULT now(),
  updated_at              timestamptz NOT NULL DEFAULT now(),
  UNIQUE (id, user_id),
  UNIQUE (user_id, address)
);
CREATE INDEX sender_user_domain    ON sender (user_id, domain);
CREATE INDEX sender_user_lastseen  ON sender (user_id, last_seen_at DESC);
CREATE INDEX sender_user_name_trgm ON sender USING gin (user_id, display_name gin_trgm_ops); -- used via search_senders()

CREATE TABLE email_template (
  id                      uuid PRIMARY KEY DEFAULT uuidv7(),
  user_id                 text NOT NULL,
  sender_id               uuid NOT NULL,
  simhash                 bigint NOT NULL,               -- 64-bit simhash of DOM skeleton; match = Hamming ≤ 3
  first_seen_at           timestamptz NOT NULL,
  last_seen_at            timestamptz NOT NULL,
  email_count             int NOT NULL DEFAULT 1,
  ai_review               jsonb,                         -- template-level criteria (L8; H7 when text is similar)
  ai_model                text,
  ai_reviewed_at          timestamptz,
  ai_source_email_id      uuid,                          -- FK added after `email` (ON DELETE SET NULL)
  classification          jsonb,                         -- cached LLM classification for (sender, template)
  classified_by           text,
  classified_at           timestamptz,
  UNIQUE (id, user_id),
  UNIQUE (sender_id, simhash),
  FOREIGN KEY (sender_id, user_id) REFERENCES sender (id, user_id) ON DELETE CASCADE
);
CREATE INDEX email_template_user_sender ON email_template (user_id, sender_id);

CREATE TABLE email (
  id                      uuid PRIMARY KEY DEFAULT uuidv7(),
  user_id                 text NOT NULL,
  mailbox_id              uuid NOT NULL,
  sender_id               uuid,
  template_id             uuid,
  provider_message_id     text NOT NULL,
  provider_thread_id      text,
  gmail_history_id        numeric(20,0) NOT NULL,        -- Message.historyId: last change applied (label-race guard)
  received_at             timestamptz NOT NULL,          -- internalDate
  subject                 text,
  from_address            citext,
  from_name               text,
  snippet                 text,                          -- NULL for security-sensitive mail
  label_ids               text[] NOT NULL DEFAULT '{}',
  is_unread               boolean NOT NULL DEFAULT true, -- mirrored from Gmail (read-only scope)
  opened_in_app_at        timestamptz,                   -- app-local read state (never written to Gmail)
  done_at                 timestamptz,                   -- app-local triage ("Done")
  pinned_at               timestamptz,
  is_starred              boolean NOT NULL DEFAULT false,
  gmail_important         boolean NOT NULL DEFAULT false,
  gmail_category          text CHECK (gmail_category IN ('promotions','updates','social','forums','personal')),
  in_trash                boolean NOT NULL DEFAULT false,
  in_spam                 boolean NOT NULL DEFAULT false,
  sender_muted            boolean NOT NULL DEFAULT false, -- denormalized from sender.muted (bulk-updated on mute)
  is_hidden               boolean GENERATED ALWAYS AS (in_trash OR in_spam OR sender_muted) STORED,
  size_bytes              int,
  html_bytes              int,                           -- decoded text/html size (clip check)
  language                text,                          -- ISO 639-1
  security_sensitive      boolean NOT NULL DEFAULT false, -- OTP / reset / magic link: minimized storage, no render/AI
  -- classification
  is_subscription         boolean NOT NULL,
  subscription_score      smallint,
  primary_type            text NOT NULL CHECK (primary_type IN ('promotional','newsletter','product_update','lifecycle',
                            'transactional','account_security','account_notice','notification','event','social',
                            'community','survey','other')),
  subtype                 text,
  secondary_tags          text[] NOT NULL DEFAULT '{}',
  type_confidence         real,
  type_source             text NOT NULL CHECK (type_source IN ('rule','sender_prior','template_cache','llm','user','pending')),
  importance              text NOT NULL DEFAULT 'normal' CHECK (importance IN ('high','normal','low')),
  importance_score        smallint CHECK (importance_score BETWEEN 0 AND 100),
  importance_reasons      text[] NOT NULL DEFAULT '{}',
  importance_expires_at   timestamptz,                   -- time-bound boosts (OTP 1h, deal ≤48h, recent shipping) → re-score
  -- header-derived facts
  list_id                 text,
  one_click_unsubscribe   boolean NOT NULL DEFAULT false,
  auth_result             text NOT NULL DEFAULT 'unknown' CHECK (auth_result IN ('pass','fail','none','unknown')),
  suspicious              boolean NOT NULL DEFAULT false, -- DMARC fail, unaligned, no ARC pass (DESIGN.md §7.8)
  esp_platform            text,
  tracker_count           smallint NOT NULL DEFAULT 0,
  utm_campaign            text,
  -- design (denormalized from email_analysis for filtering/sorting)
  design_status           text NOT NULL DEFAULT 'pending'
                          CHECK (design_status IN ('pending','done','failed','skipped','plain_text')),
  design_ai_state         text NOT NULL DEFAULT 'pending'
                          CHECK (design_ai_state IN ('pending','queued','done','from_template','flagged','failed','not_applicable')),
  design_score            smallint CHECK (design_score BETWEEN 0 AND 100),
  design_band             text CHECK (design_band IN ('excellent','good','needs_work','poor')),
  design_capped           boolean,
  design_provisional      boolean,                       -- excluded from Good/Bad chips (DESIGN-SCORE §3.1)
  design_issues           text[] NOT NULL DEFAULT '{}'
                          CHECK (design_issues <@ ARRAY['image_only','contrast','mobile','clipped','broken_images']::text[]),
  design_confidence       text CHECK (design_confidence IN ('high','medium','low')),
  font_families           text[] NOT NULL DEFAULT '{}' CHECK (cardinality(font_families) <= 12),
                          -- display-canonical names of USED primary families (DESIGN.md §8.1): catalog spelling if known,
                          -- else the designer's; one entry per lower(name); top 12 by share (writer truncates);
                          -- excludes generics and 'No font set'. Raw facts live in email_analysis.features.fonts
  uses_web_fonts          boolean NOT NULL DEFAULT false, -- a used family (share ≥ 1%) is declared as a web font in this email
  -- deals (denormalized)
  has_deal                boolean NOT NULL DEFAULT false,
  deal_has_code           boolean NOT NULL DEFAULT false,
  deal_ends_at            timestamptz,                   -- LATEST expiry among the email's deals
  -- search: computed at INSERT from subject + sender + excerpt; the excerpt itself is NOT stored
  search_tsv              tsvector NOT NULL DEFAULT ''::tsvector,
  created_at              timestamptz NOT NULL DEFAULT now(),
  updated_at              timestamptz NOT NULL DEFAULT now(),
  UNIQUE (id, user_id),
  UNIQUE (mailbox_id, provider_message_id),
  FOREIGN KEY (mailbox_id, user_id)  REFERENCES mailbox (id, user_id) ON DELETE CASCADE,
  FOREIGN KEY (sender_id, user_id)   REFERENCES sender (id, user_id) ON DELETE SET NULL (sender_id),
  FOREIGN KEY (template_id, user_id) REFERENCES email_template (id, user_id) ON DELETE SET NULL (template_id)
) WITH (fillfactor = 85);

ALTER TABLE email_template ADD FOREIGN KEY (ai_source_email_id) REFERENCES email (id) ON DELETE SET NULL;

-- Timeline + covering columns for facet counts (is_unread deliberately NOT included → keeps HOT updates).
CREATE INDEX email_user_timeline ON email (user_id, received_at DESC, id DESC)
  INCLUDE (primary_type, design_band, importance, has_deal, is_subscription, sender_id, mailbox_id)
  WHERE NOT is_hidden;
CREATE INDEX email_user_type     ON email (user_id, primary_type, received_at DESC) WHERE NOT is_hidden;
CREATE INDEX email_user_score    ON email (user_id, design_score DESC, id DESC) WHERE NOT is_hidden AND design_score IS NOT NULL;
CREATE INDEX email_user_sender   ON email (user_id, sender_id, received_at DESC);            -- also serves the sender FK
CREATE INDEX email_user_template ON email (user_id, template_id) WHERE template_id IS NOT NULL; -- template FK
CREATE INDEX email_user_attention ON email (user_id, received_at DESC)
  WHERE importance = 'high' AND done_at IS NULL AND NOT is_hidden;
CREATE INDEX email_user_deals    ON email (user_id, deal_ends_at) WHERE has_deal;
CREATE INDEX email_importance_exp ON email (importance_expires_at) WHERE importance_expires_at IS NOT NULL;
CREATE INDEX email_user_search   ON email USING gin (user_id, search_tsv);                   -- used via search_emails()

CREATE TABLE email_analysis (
  email_id                uuid PRIMARY KEY,
  user_id                 text NOT NULL,
  scoring_version         text NOT NULL,
  renderer_version        text,
  features                jsonb NOT NULL,
  checks                  jsonb NOT NULL,                -- [{id,status,s,value}]
  pillar_scores           jsonb NOT NULL,
  raw_score               real,
  caps                    text[] NOT NULL DEFAULT '{}',
  confidence              real NOT NULL,
  ai_review               jsonb,                         -- per criterion: level, evidence (URLs/emails stripped), source
  ai_model                text,
  trust                   jsonb,                         -- Sender Trust & Compliance badge
  screenshot_keys         jsonb,                         -- {desktop, mobile, images_off, thumb}: private Blob pathnames
  screenshots_full_until  timestamptz,                   -- full-size kept until; then thumbnail only
  render_ms               int,
  error                   text,
  analyzed_at             timestamptz NOT NULL DEFAULT now(),
  FOREIGN KEY (email_id, user_id) REFERENCES email (id, user_id) ON DELETE CASCADE
);
CREATE INDEX email_analysis_version ON email_analysis (scoring_version);
CREATE INDEX email_analysis_shots   ON email_analysis (screenshots_full_until) WHERE screenshots_full_until IS NOT NULL;

CREATE TABLE deal (
  id                      uuid PRIMARY KEY DEFAULT uuidv7(),
  email_id                uuid NOT NULL,
  user_id                 text NOT NULL,
  sender_id               uuid,
  kind                    text NOT NULL CHECK (kind IN ('percent_off','amount_off','bogo','free_shipping','gift','other')),
  value                   numeric(10,2),
  currency                text CHECK (currency ~ '^[A-Z]{3}$'),
  is_up_to                boolean NOT NULL DEFAULT false,
  min_spend               numeric(10,2),
  code                    text,                          -- may be per-recipient → private, never aggregated
  starts_at               timestamptz,
  ends_at                 timestamptz,                   -- undated deals: received_at + 14d, low confidence
  ends_at_confidence      real,
  source                  text NOT NULL CHECK (source IN ('jsonld','regex','llm')),
  created_at              timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT deal_dedupe UNIQUE NULLS NOT DISTINCT (email_id, kind, value, code),
  FOREIGN KEY (email_id, user_id)  REFERENCES email (id, user_id) ON DELETE CASCADE,
  FOREIGN KEY (sender_id, user_id) REFERENCES sender (id, user_id) ON DELETE SET NULL (sender_id)
);
CREATE INDEX deal_user_ends   ON deal (user_id, ends_at);
CREATE INDEX deal_user_sender ON deal (user_id, sender_id) WHERE sender_id IS NOT NULL;

-- Every Gmail message id we have seen, with its processing state. Content-free.
-- Replaces a separate skip table; makes the sync cursor safe to advance (DESIGN.md §5.5).
CREATE TABLE message_ledger (
  mailbox_id              uuid NOT NULL,
  user_id                 text NOT NULL,
  provider_message_id     text NOT NULL,
  state                   text NOT NULL CHECK (state IN ('pending','pending_full','stored','skipped','failed')),
  reason                  text CHECK (reason IN ('personal','sent','draft','chat','spam','auto_reply','parse_error',
                                                 'gmail_error','too_large')),
  source                  text NOT NULL CHECK (source IN ('backfill','sync','resync','reconcile')),
  attempts                smallint NOT NULL DEFAULT 0,
  next_attempt_at         timestamptz,
  pending_label_delta     jsonb,                         -- label changes seen before the row was stored
  delta_history_id        numeric(20,0),
  classifier_version      text,                          -- re-evaluate skipped rows when the classifier changes
  updated_at              timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (mailbox_id, provider_message_id),
  FOREIGN KEY (mailbox_id, user_id) REFERENCES mailbox (id, user_id) ON DELETE CASCADE
);
CREATE INDEX message_ledger_redrive ON message_ledger (next_attempt_at) WHERE state IN ('pending','pending_full');

CREATE TABLE sync_run (                               -- only backfill / resync / failed runs are logged; 30-day retention
  id                      uuid PRIMARY KEY DEFAULT uuidv7(),
  user_id                 text NOT NULL,
  mailbox_id              uuid NOT NULL,
  kind                    text NOT NULL CHECK (kind IN ('backfill','incremental','reconcile','resync')),
  status                  text NOT NULL CHECK (status IN ('running','done','failed','cancelled')),
  stats                   jsonb NOT NULL DEFAULT '{}',
  error                   text,                          -- error code only, never message content
  workflow_run_id         text,
  started_at              timestamptz NOT NULL DEFAULT now(),
  finished_at             timestamptz,
  FOREIGN KEY (mailbox_id, user_id) REFERENCES mailbox (id, user_id) ON DELETE CASCADE
);
CREATE INDEX sync_run_mailbox ON sync_run (mailbox_id, started_at DESC);
CREATE INDEX sync_run_started ON sync_run (started_at);
CREATE UNIQUE INDEX sync_run_workflow ON sync_run (workflow_run_id) WHERE workflow_run_id IS NOT NULL;

CREATE TABLE saved_view (                             -- user-created views only; built-in views are defined in code
  id                      uuid PRIMARY KEY DEFAULT uuidv7(),
  user_id                 text NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  name                    text NOT NULL,
  filters                 jsonb NOT NULL,                -- same schema as the filter state (Zod)
  sort                    text NOT NULL DEFAULT 'received_desc',
  position                int NOT NULL DEFAULT 0,
  created_at              timestamptz NOT NULL DEFAULT now(),
  UNIQUE (user_id, name)
);

CREATE TABLE user_feedback (                          -- that user's corrections → that user's personalization only
  id                      uuid PRIMARY KEY DEFAULT uuidv7(),
  user_id                 text NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  email_id                uuid,
  sender_id               uuid,
  field                   text NOT NULL CHECK (field IN ('primary_type','importance','is_subscription','is_personal','design_disagree')),
  old_value               text,
  new_value               text,
  created_at              timestamptz NOT NULL DEFAULT now(),
  FOREIGN KEY (email_id, user_id)  REFERENCES email (id, user_id) ON DELETE CASCADE,
  FOREIGN KEY (sender_id, user_id) REFERENCES sender (id, user_id) ON DELETE CASCADE
);
CREATE INDEX user_feedback_user   ON user_feedback (user_id, created_at DESC);
CREATE INDEX user_feedback_email  ON user_feedback (email_id)  WHERE email_id IS NOT NULL;
CREATE INDEX user_feedback_sender ON user_feedback (sender_id) WHERE sender_id IS NOT NULL;

-- Explicit, per-message consent for staff to view one email's screenshot/analysis (Limited Use: "no humans reading").
CREATE TABLE review_share (
  email_id                uuid NOT NULL,
  user_id                 text NOT NULL,
  reason                  text NOT NULL CHECK (reason IN ('design_disagree','support')),
  shared_at               timestamptz NOT NULL DEFAULT now(),
  expires_at              timestamptz NOT NULL,          -- 30 days
  PRIMARY KEY (email_id),
  FOREIGN KEY (email_id, user_id) REFERENCES email (id, user_id) ON DELETE CASCADE
);

CREATE TABLE llm_usage (                              -- metering; no content
  id                      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id                 text NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  day                     date NOT NULL,
  purpose                 text NOT NULL CHECK (purpose IN ('classify','design_review','copy_review','deal_verify')),
  model                   text NOT NULL,
  batch                   boolean NOT NULL DEFAULT false,
  requests                int NOT NULL DEFAULT 0,
  input_tokens            bigint NOT NULL DEFAULT 0,
  cached_input_tokens     bigint NOT NULL DEFAULT 0,
  output_tokens           bigint NOT NULL DEFAULT 0,
  UNIQUE (user_id, day, purpose, model, batch)
);

CREATE TABLE llm_budget (                             -- atomic per-user spend reservation (DESIGN.md §11.8)
  user_id                 text NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  day                     date NOT NULL,
  reserved_usd            numeric(10,4) NOT NULL DEFAULT 0,
  PRIMARY KEY (user_id, day)
);

CREATE TABLE data_request (
  id                      uuid PRIMARY KEY DEFAULT uuidv7(),
  user_id                 text NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  kind                    text NOT NULL CHECK (kind IN ('export','delete_account','disconnect_purge')),
  status                  text NOT NULL CHECK (status IN ('queued','running','done','failed')),
  result_blob_key         text,
  requested_at            timestamptz NOT NULL DEFAULT now(),
  completed_at            timestamptz
);
CREATE UNIQUE INDEX data_request_one_active ON data_request (user_id, kind) WHERE status IN ('queued','running');

-- Security-relevant events. No email content. Pseudonymous after account deletion; kept 1 year.
CREATE TABLE audit_log (
  id                      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id                 text,                          -- NOT a FK: survives account deletion (pseudonymous id)
  actor                   text NOT NULL,                 -- 'user' | 'system' | 'admin:<id>'
  action                  text NOT NULL,
  target                  text,
  ip_hash                 text,                          -- HMAC(ip)
  user_agent              text,
  metadata                jsonb NOT NULL DEFAULT '{}',
  created_at              timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX audit_log_user    ON audit_log (user_id, created_at DESC);
CREATE INDEX audit_log_created ON audit_log USING brin (created_at);

-- Deferred Blob deletion: rows are enqueued by trigger when analyses are deleted (incl. cascades).
CREATE TABLE blob_gc (
  id                      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id                 text NOT NULL,
  pathname                text NOT NULL,
  enqueued_at             timestamptz NOT NULL DEFAULT now()
);
-- SECURITY DEFINER (owned by app_system, §4.3) so it also works inside FK cascades, whatever the tenant context.
CREATE FUNCTION enqueue_blob_gc() RETURNS trigger
LANGUAGE plpgsql SECURITY DEFINER SET search_path = pg_catalog, public, pg_temp AS $$
BEGIN
  IF OLD.screenshot_keys IS NOT NULL THEN
    INSERT INTO blob_gc (user_id, pathname)
    SELECT OLD.user_id, v FROM jsonb_each_text(OLD.screenshot_keys) AS t(k, v) WHERE v IS NOT NULL;
  END IF;
  RETURN OLD;
END $$;
CREATE TRIGGER email_analysis_blob_gc AFTER DELETE ON email_analysis
  FOR EACH ROW EXECUTE FUNCTION enqueue_blob_gc();
```

**Blob layout:** every pathname is prefixed `u/{user_id}/m/{mailbox_id}/`:
- `…/tmp/{batch}.ndjson.gz` holds pipeline working copies, one object per fetch batch.
- `…/e/{email_id}/{desktop|mobile|off|thumb}.webp` holds screenshots.

Mailbox and account purges delete **by prefix**. `blob_gc` handles per-email deletions.

## 4. Roles, RLS and system access

### 4.1 Roles

The Vercel–Neon integration injects the *owner* role, `neondb_owner`. That role is a member of
`neon_superuser`, which has **BYPASSRLS**, and the review confirmed it sees all 130k rows even
with `FORCE`. So the app must **never** run as the owner.

```sql
-- Create via SQL (NOT the Neon console: console/API roles join neon_superuser → BYPASSRLS).
CREATE ROLE app_rw     LOGIN PASSWORD :'app_rw_password' NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE NOINHERIT;
CREATE ROLE app_system NOLOGIN NOSUPERUSER NOBYPASSRLS;   -- owns SECURITY DEFINER functions only

GRANT USAGE ON SCHEMA public TO app_rw, app_system;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_rw;
GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO app_rw;
ALTER DEFAULT PRIVILEGES FOR ROLE neondb_owner IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_rw;
REVOKE UPDATE, DELETE ON audit_log FROM app_rw;          -- append-only from the app
REVOKE ALL ON beta_allowlist FROM app_rw;                -- only readable through is_invited()
```

- **Connection strings:**
  - `DATABASE_URL` (pooled) → `app_rw`, used by `web` and the Inngest functions.
  - `DATABASE_URL_OWNER` (unpooled) → `neondb_owner`, available **only** to the CI migration
    job.
  - The renderer project holds **no** database credentials.
- **Boot assertion.** The app refuses to start if
  `SELECT rolsuper OR rolbypassrls OR pg_has_role(current_user, 'neon_superuser', 'MEMBER') FROM pg_roles WHERE rolname = current_user`
  returns true.

### 4.2 Tenant policies

On every tenant table: `mailbox`, `gmail_quota`, `user_settings`, `sender`, `email_template`,
`email`, `email_analysis`, `deal`, `message_ledger`, `sync_run`, `saved_view`,
`user_feedback`, `review_share`, `llm_usage`, `llm_budget`, `data_request`, `blob_gc`.

```sql
DO $$
DECLARE t text;
BEGIN
  FOREACH t IN ARRAY ARRAY['mailbox','gmail_quota','user_settings','sender','email_template','email','email_analysis',
    'deal','message_ledger','sync_run','saved_view','user_feedback','review_share','llm_usage','llm_budget',
    'data_request','blob_gc']
  LOOP
    EXECUTE format('ALTER TABLE %I ENABLE ROW LEVEL SECURITY', t);
    EXECUTE format('ALTER TABLE %I FORCE ROW LEVEL SECURITY', t);
    EXECUTE format($p$CREATE POLICY tenant ON %I TO app_rw
      USING      (user_id = NULLIF(current_setting('app.user_id', true), ''))
      WITH CHECK (user_id = NULLIF(current_setting('app.user_id', true), ''))$p$, t);
  END LOOP;
END $$;

-- audit_log: anyone may append (incl. system/anonymous events); users read only their own; no update/delete.
ALTER TABLE audit_log ENABLE ROW LEVEL SECURITY;
ALTER TABLE audit_log FORCE  ROW LEVEL SECURITY;
CREATE POLICY audit_insert   ON audit_log FOR INSERT TO app_rw WITH CHECK (true);
CREATE POLICY audit_read_own ON audit_log FOR SELECT TO app_rw
  USING (user_id = NULLIF(current_setting('app.user_id', true), ''));
```

- `withUser(userId, tx => …)` opens a transaction on the `pg` Pool and first runs
  `SELECT set_config('app.user_id', $1, true)`.
  - It's **transaction-local**, which is required under Neon's PgBouncer transaction mode.
  - An unset or empty setting matches **no rows** (fails closed). After first use in a pooled
    session the value reads as `''`, which `NULLIF` handles.
  - The DAL also asserts the setting is non-empty, so a missing `withUser` raises instead of
    silently returning nothing.
- Postgres attaches RLS to a table, not to a query. Queries on these tables therefore go
  through the DAL, which always sets the context.

### 4.3 System functions (`SECURITY DEFINER`, owned by `app_system`)

A few operations have to run without a single tenant context: the push lookup, the watch and
reconcile sweeps, ledger re-drive, retention, and blob GC. They go through
minimal-column `SECURITY DEFINER` functions owned by `app_system`. `app_system` gets column
grants plus an explicit `TO app_system` policy, and never BYPASSRLS.

The same pattern fixes **search under RLS**. The operators behind `@@`, trigram `%`/`ILIKE`
and `@>` are not `LEAKPROOF`, so under RLS the GIN index was only used on its `user_id` column
(1.1 ms became 13 ms, reading the user's entire heap). Search therefore runs inside definer
functions that apply the tenant predicate **explicitly** from `app.user_id`.

```sql
GRANT SELECT (id, user_id, provider, email_address, status, watch_expires_at, last_push_at, last_synced_at,
              needs_reauth_since) ON mailbox TO app_system;
GRANT SELECT (id, user_id, search_tsv, received_at, is_hidden) ON email TO app_system;
GRANT SELECT (id, user_id, display_name, address) ON sender TO app_system;
GRANT SELECT (mailbox_id, user_id, provider_message_id, state, next_attempt_at) ON message_ledger TO app_system;
GRANT SELECT (email_id, user_id, screenshots_full_until) ON email_analysis TO app_system;
GRANT SELECT, INSERT, DELETE ON blob_gc TO app_system;
GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO app_system;
CREATE POLICY system_read ON mailbox        FOR SELECT TO app_system USING (true);
CREATE POLICY system_read ON email          FOR SELECT TO app_system USING (true);
CREATE POLICY system_read ON sender         FOR SELECT TO app_system USING (true);
CREATE POLICY system_read ON message_ledger FOR SELECT TO app_system USING (true);
CREATE POLICY system_read ON email_analysis FOR SELECT TO app_system USING (true);
CREATE POLICY system_all  ON blob_gc        FOR ALL    TO app_system USING (true) WITH CHECK (true);

-- Push webhook: address → mailbox (no tenant context yet).
CREATE FUNCTION public.lookup_mailbox_for_push(p_email text)
RETURNS TABLE (mailbox_id uuid, user_id text)
LANGUAGE sql STABLE SECURITY DEFINER SET search_path = pg_catalog, pg_temp AS $$
  SELECT m.id, m.user_id FROM public.mailbox m
  WHERE m.provider = 'gmail'
    AND m.email_address OPERATOR(public.=) p_email::public.citext   -- citext's case-insensitive =; it is NOT on the
    AND m.status IN ('active', 'needs_reauth')                      -- hardened search_path (plain = would silently
                                                                    -- fall back to case-sensitive text = and miss)
$$;

-- Tenant-scoped full-text search (explicit tenant predicate → full GIN index use).
CREATE FUNCTION public.search_emails(q text, lim int DEFAULT 50)
RETURNS TABLE (id uuid, rank real)
LANGUAGE sql STABLE SECURITY DEFINER SET search_path = pg_catalog, public, pg_temp AS $$
  SELECT e.id, ts_rank_cd(e.search_tsv, websearch_to_tsquery('simple', q))
  FROM public.email e
  WHERE e.user_id = NULLIF(current_setting('app.user_id', true), '')
    AND e.search_tsv @@ websearch_to_tsquery('simple', q)
    AND NOT e.is_hidden
  ORDER BY 2 DESC LIMIT least(lim, 200)
$$;
-- Also: search_senders(q), list_mailboxes_due_for_watch(before timestamptz, lim int),
--       list_mailboxes_stale_push(older_than interval, lim int), list_ledger_redrive(lim int),
--       list_expired_screenshots(lim int), take_blob_gc(lim int) — same pattern, paginated.

GRANT app_system TO neondb_owner WITH SET TRUE;         -- lets the migration role assign function ownership
GRANT CREATE ON SCHEMA public TO app_system;            -- required only while changing ownership …
ALTER FUNCTION public.lookup_mailbox_for_push(text) OWNER TO app_system;
ALTER FUNCTION public.search_emails(text, int)      OWNER TO app_system;
ALTER FUNCTION public.enqueue_blob_gc()             OWNER TO app_system;
REVOKE CREATE ON SCHEMA public FROM app_system;         -- … and revoked immediately after
REVOKE ALL ON FUNCTION public.lookup_mailbox_for_push(text), public.search_emails(text, int) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION public.lookup_mailbox_for_push(text), public.search_emails(text, int) TO app_rw;
```

**CI tests** (they run against a Neon **schema-only** branch):
- `app_rw` has no BYPASSRLS.
- Cross-tenant `SELECT`/`UPDATE`/`INSERT` return 0 rows or error.
- A cross-tenant composite FK insert errors.
- Each system function returns rows with no `app.user_id` set.
- `search_emails` plans with `Index Cond … search_tsv @@`.

## 5. Query patterns

- **Lists** are built with **dynamic WHERE clauses** in Drizzle, never with the catch-all
  `($x IS NULL OR col = $x)`. Under a generic plan that scanned every heap page: 18.6 ms vs
  0.15 ms. They're keyset-paginated on `(received_at, id)`:

```sql
SELECT id, received_at, subject, from_name, snippet, primary_type, importance, design_score, design_band,
       design_provisional, has_deal, deal_ends_at, is_unread, opened_in_app_at
FROM email
WHERE user_id = $1 AND NOT is_hidden
  AND is_subscription = true                 -- scope toggle, when set
  AND primary_type = ANY($types)             -- only when the facet is set
  AND (received_at, id) < ($cursor_ts, $cursor_id)
ORDER BY received_at DESC, id DESC
LIMIT 50;
```

- **Facet counts:**
  - One `GROUPING SETS` query per filter change. It's mostly an index-only scan thanks to the
    `INCLUDE` columns (23 ms → 11 ms at 20k rows).
  - Cached per `(user, filter-hash)` for 30s.
  - Counts above 999 display as "999+".
- **Search**: `SELECT … FROM search_emails($q) s JOIN email e USING (id)`, with a prefix `:*`
  on the last token for search-as-you-type. Sender search goes through `search_senders()`.
- **Gallery** (`queries/gallery.ts`): its search is a plain WHERE condition over the user's designs
  (every word a prefix, the sender's address, accent-free names; `lib/gallery-search.ts`) rather
  than `search_emails()`, so totals, pages and counts are never cut at 200 matches. Its counts are
  read with every page, never cached (≈ 15 ms on 625 designs), so they always match the list.
- **Font family filter**:
  - The option list groups spellings case-insensitively:
    ```sql
    SELECT lower(f) AS k, mode() WITHIN GROUP (ORDER BY f) AS label, array_agg(DISTINCT f) AS vals, count(*) AS n
    FROM email, unnest(font_families) f
    WHERE user_id = $1 AND NOT is_hidden
    GROUP BY 1 ORDER BY n DESC LIMIT 200;
    ```
  - The filter is `font_families && $vals::text[]`, where `$vals` is the union of the selected
    options' `vals`. That gives OR within the facet.
  - "Uses web fonts" is a separate `uses_web_fonts = true` predicate, ANDed with the families.
  - Font names are **not** added to `search_tsv`.
- **Design issue chips**: `design_issues @> ARRAY[$chip]` as a filter over the user's timeline
  rows (≈12 ms at 20k). There's no GIN index, because it wouldn't be used under RLS and would
  cost a write on every re-score.
- **Sender aggregates** are incremented only when `INSERT … ON CONFLICT … RETURNING (xmax = 0)`
  reports a real insert. `unread_count` and `read_rate_60d` are recounted per sender inside the
  same transaction, and fully recomputed nightly.
- **Template matching** runs under `pg_advisory_xact_lock(hashtextextended(sender_id::text, 0))`
  with `bit_count((simhash # $h)::bit(64)) <= 3`, so concurrent workers can't create duplicate
  near-identical templates.
- **Label deltas** (race-safe):
  `UPDATE email SET is_unread = $u, gmail_history_id = $h WHERE mailbox_id = $m AND provider_message_id = $id AND gmail_history_id < $h`.
  - If the row doesn't exist yet, the delta goes on `message_ledger.pending_label_delta` and is
    applied at insert time if newer than `Message.historyId`.
- **Cursor CAS**:
  `UPDATE mailbox SET history_id = $new WHERE id = $id AND (history_id IS NULL OR history_id < $new::numeric)`.
  - It runs in the same transaction as the ledger inserts. `$new` is bound as a string.

## 6. Retention & deletion

| Data | Where | Retention |
|---|---|---|
| Pipeline working copies (sanitized HTML batches) | Private Blob `…/tmp/` | Deleted when analysis finishes. The sweeper removes anything older than 24h. `cacheControlMaxAge: 60`. |
| Full-size screenshots | Private Blob | `screenshot_retention_days` (default 30), computed at sweep time from `user_settings`. After that a ≤ 25 KB thumbnail is kept; full analysis can be re-rendered on demand. |
| Security-sensitive mail | Postgres | Subject, sender and time only. Never rendered, screenshotted or sent to AI. |
| Email metadata, features, scores, deals | Postgres | Until the user deletes it, disconnects, or the message is permanently deleted in Gmail (history `messageDeleted` → hard delete + `blob_gc`) |
| Email body | **Never stored.** Viewing fetches it live from Gmail. The search index is a `tsvector` derived from a non-persisted excerpt. | — |
| `message_ledger` (content-free) | Postgres | `skipped` rows older than 400 days purged. The rest live with the mailbox. |
| `sync_run` | Postgres | 30 days |
| `audit_log` | Postgres | 1 year, pseudonymous after account deletion |
| Export archives | Private Blob | 7 days |
| Mailbox in `needs_reauth` | — | Purged 30 days after `needs_reauth_since`, or on a RISC `tokens-revoked` event |
| Backups | Neon point-in-time recovery | Deleted data persists in PITR history for the plan's window (7 days on Launch). This is disclosed in the privacy policy. |

**Disconnect purge** (a durable job; see DESIGN.md §5.7 for the external steps):
1. Batch-delete `email` rows (5,000 per transaction; cascades to analysis, deal, feedback,
   review_share, with `blob_gc` enqueued).
2. Delete the `mailbox` row (cascades to gmail_quota, message_ledger, sync_run).
3. Delete senders left with no emails:
   `DELETE FROM sender s WHERE s.user_id = $1 AND NOT EXISTS (SELECT 1 FROM email e WHERE e.user_id = s.user_id AND e.sender_id = s.id)`.
   This cascades to templates and sender feedback.
   The nightly `daily-maintenance` run removes orphan senders the same way, but keeps any sender
   that carries the user's choices (muted, a type override, an importance bias, unsubscribed, or
   feedback about the sender), so that sender's later mail still arrives muted or overridden. The
   disconnect purge removes those only with the user's last mailbox.
4. Delete Blob objects by prefix `u/{user}/m/{mailbox}/`.
5. Run a second sweep.
6. Write an `audit_log` entry.

**Account deletion** runs the same purge for every mailbox, then deletes the Better Auth user
(cascading everything else), then deletes the prefix `u/{user}/`.

## 7. Scale notes

- **Row sizes.** An `email` row is now ~1.2 KB. `search_text` is gone: it averaged 1.26 KB of a
  2.2 KB row. An `email_analysis` row is ~5–8 KB.
- **Volume.** 10M emails ≈ 12 GB of rows plus indexes, and ~70 GB of analysis. That's
  comfortable on one Neon database.
- **Partitioning.** Hash-partitioning by `user_id` is a contained later migration (roughly 50–100M
  rows), since every index leads with `user_id`.
- **Write amplification.** `fillfactor = 85`, and `is_unread` is kept out of indexes, which
  keeps read-state mirroring HOT. There's no `analyzing` status write (Inngest tracks
  in-flight work), and no GIN on `design_issues`.
- **Deletion speed.** Deleting a user with 5k emails, 300 senders and 600 templates took 21.2s
  before the FK indexes and composite-FK support indexes, and 0.12s after (measured).
